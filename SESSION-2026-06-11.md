## 7. Soft + Hard delete (orders / invoices / users)

[viralefy_core@704725d](https://github.com/Viralefy/viralefy_core/commit/704725d) + [viralefy_backoffice@ba49167](https://github.com/Viralefy/viralefy_backoffice/commit/ba49167)

**Modelo de 2 camadas:**
- Admin com `admins:manage` → **soft delete** (deleted_at + deleted_by_admin_id + delete_reason). Row fica no DB.
- Superadmin → **hard delete** (DELETE FROM). Cascading via FKs.
- Superadmin → **restore**.

**Migration 045**: 3 colunas em orders + invoices, 2 em users (já tinha
`deleted_at` desde 020). Índice parcial WHERE deleted_at IS NOT NULL.

**Endpoints**: 9 rotas
```
DELETE /v1/admin/{orders,invoices,users}/{id}           soft  (admins:manage)
DELETE /v1/admin/{orders,invoices,users}/{id}/hard      hard  (RequireSuperadmin)
POST   /v1/admin/{orders,invoices,users}/{id}/restore   undo  (RequireSuperadmin)
```

Novo middleware `RequireSuperadmin` (role==superadmin, sem RBAC lookup).

**UI**: `components/DeleteActions.tsx` — "Danger zone" reusable. Soft
button (admin+) com prompt de motivo. Hard + Restore (superadmin)
com confirmação dupla. Badge "Soft-deleted" quando aplicável.

## 9. Honeypot — superadmin invisível pro admin comum

[viralefy_core@e8d2620](https://github.com/Viralefy/viralefy_core/commit/e8d2620) + [viralefy_backoffice@9937c4e](https://github.com/Viralefy/viralefy_backoffice/commit/9937c4e)

**Migration 046**: `admin_honeypot_log` (actor + target + action +
attempted_role + IP + UA + timestamp) com 2 índices.

**Defesa em 4 camadas:**

1. **Camuflagem**: na listagem de admins, superadmin aparece com
   `role="manager"` pra non-superadmin callers (indistinguível de
   managers reais).
2. **Fake success**: admin tenta editar role ou deletar superadmin →
   resposta 200 com adminPublicView falso refletindo a "mudança". DB
   intocado.
3. **Shadow-delete**: após fake delete, target some da lista DAQUELE
   actor especificamente (outros admins continuam vendo normal).
4. **Audit log**: cada tentativa grava em admin_honeypot_log.

**Endpoint**: `GET /v1/admin/honeypot` (RequireSuperadmin) com hidratação
de email/name do actor + target.

**UI**: `/honeypot` page com:
- **Top Suspects** (agregado por actor com count) — quem repete é vagabundo
- **Timeline** das tentativas com action badges (delete=vermelho, update_role=amarelo)

DeleteActions component: removido qualquer hint de superadmin pra não
vazar a existência da role mais alta.

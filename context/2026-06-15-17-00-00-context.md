# Round 29 — UX do erro 409 (continuação do round 28)

## Por quê

Round 28 corrigiu o **bug raiz** (soft-deleted bloqueava recadastro).
Mas no diagnóstico ficou claro que o user (Lucas) **clicou 3x** no
register antes de desistir — porque a mensagem era apenas "conflict".
Mesmo agora que o bug raiz está corrigido, **email já cadastrado
LEGÍTIMO continua dando 409**. UX precisa ser decente.

## Mudanças

### Backend (viralefy_auth + viralefy_core)

`auth_service.go` e `user_auth_service.go`:
```go
return nil, fmt.Errorf("email already registered: %w", domain.ErrConflict)
```
Wrap preserva `errors.Is(domain.ErrConflict)` mas a mensagem fica útil.

`response.go` em ambos:
```go
case errors.Is(err, domain.ErrConflict):
    msg = strings.TrimSuffix(err.Error(), ": "+domain.ErrConflict.Error())
```
Tira o sufixo ": conflict" vestigial do wrap. Body final:
```json
{"error":{"code":"CONFLICT","message":"email already registered","trace_id":"..."}}
```

### Frontend (viralefy_front)

`lib/api.ts`:
- Nova class `ApiError(status, code, message)` que preserva metadata da
  resposta de erro. Antes era `Error` genérico — caller não tinha como
  distinguir 409 de 400 ou 422 e mostrava o mesmo alerta opaco.

`app/register/page.tsx`:
- `error` agora é `ReactNode | null` (era `string | null`) — permite
  render de JSX com links.
- Branch específico para `ApiError.code === "CONFLICT"`:
  > This email is already registered. **Sign in** or **recover your password**.
- Branch para `RATE_LIMITED`: "Too many attempts. Please wait a few seconds…"

`app/login/page.tsx`:
- `ApiError.code === "UNAUTHORIZED"` → "Incorrect email or password." (mantém
  anti-enum: a mensagem não distingue "email não existe" de "senha errada").
- `RATE_LIMITED` tratado igual ao register.

## Princípios mantidos

- **Anti-enum no login**: a mensagem unificada cobre tanto email-não-existe
  quanto senha-errada. Não vazamos existência de conta.
- **Anti-enum no reset password**: já era no-op silencioso pra email não
  encontrado; não tocado.
- **errors.Is preserva contrato**: o wrap fmt.Errorf usa %w, então
  todos os call sites que checam `errors.Is(domain.ErrConflict)` continuam
  funcionando.

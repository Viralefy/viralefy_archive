Features adicionadas ao viralefy em 2026-05-27 (sobre o MVP inicial):

- **Categorias de serviço**: tabela `categories` (seguidores/engajamento/visualizacoes/servicos); `plans.category`. Front mostra abas por categoria; backoffice tem select de categoria no plano.
- **Auth de usuário na loja** (separado do admin): `POST /v1/auth/user/register`, `POST /v1/auth/user/login` → JWT com `role:"user"`. Middleware `UserAuth`. Tokens admin e user usam o MESMO segredo, então a validação checa o claim `role` (admin exige `role:"admin"`, user exige `role:"user"`) — sem isso um token de user passaria nas rotas admin.
- **Autocadastro no checkout**: `POST /v1/checkout` não recebe mais senha; cria a conta, gera senha forte (`application.GeneratePassword`, crypto/rand) e envia por e-mail (a senha NÃO volta na resposta nem vai pro log). Se o e-mail existe, reaproveita a conta.
- **Histórico de compras**: `GET /v1/me/orders` (UserAuth) → `domain.OrderView` (order + plan_name via JOIN). Página `/account` no front.
- **Multimoeda**: tabela `currencies` (rate = unidades por 1 BRL; `settlement_code`; `display_enabled`; `decimals`). Regra exibe≠cobra: USD tem `display_enabled=true` e `settlement_code=USDT` (mostra dólar, cobra USDT); USDT é só liquidação (display off). `CurrencyService.QuoteFromBRL` resolve display+settlement. Pedido grava display_currency/display_amount/settlement_currency/settlement_amount. Front converte preço client-side via rates de `/v1/currencies` (seletor no header, persistido em localStorage); backoffice tem página `/currencies` pra editar taxas. Admin: `GET/PUT /v1/admin/currencies/{code}`.

Débitos: checkout cria user+order+email sem transação (sem outbox); JWT ainda HS256 (ver [[viralefy-stack-initial-build-fixes]]).

## Atualização v3 (2026-05-27, mesma sessão)

- **Preço manual por moeda** (substituiu a conversão por taxa): tabela `plan_prices(plan_id, currency_code, amount TEXT)`. `Plan.Prices` (map agregado via json_object_agg no plan_repo). `CurrencyService.QuoteForPlan` usa preço manual com fallback de conversão. Backoffice tem form de preço por moeda (criar + editar). Front usa `priceFor(plan, currency)` (lib/format.ts), sem conversão. `currencies.rate` agora é só baseline de seed/fallback.
- **Planos-base de seguidores**: 7 planos com valores BRL definidos pelo cliente (100=9,90 / 250=18,90 / 500=35,90 / 1000=69,90 / 10k=399,90 / 100k=3199,90 / 1M=11999,99). Inputs de plano agora têm tags JSON (antes `followers_qty` etc. não faziam bind — bug latente corrigido).

- **RBAC/ABAC**: tabelas `roles`/`role_permissions`, `admins.role`. Papéis: superadmin/manager/support/viewer. Permissões `<recurso>:<ação>` em `domain/authz.go` (Principal.Can, superadmin bypass). Middleware `RequirePermission(perm)` por rota no router. `GET /v1/admin/me` expõe principal p/ gating de UI no backoffice (lib/auth.ts `can()`). Falha do provider degrada gracioso (pedido criado, sem payment data, logado). Seed insere os 3 gateways de forma idempotente (manual ativo, woovi+heleket inativos até admin configurar).
